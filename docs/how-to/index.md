# How to

Understand, choose, and apply Spec Kit practices to your project work.
These guides cover development approaches, project contexts, complex features,
and specification maintenance.

| Goal | Guide |
| --- | --- |
| Understand the development approach | [Understand Spec-Driven Development](sdd.md) |
| Turn an idea into a mockup and business rules before the first spec | [Design the product first](studio.md) |
| Start with code you already have | [Adopt Spec Kit in an existing project](existing-projects.md) |
| Work across projects in one repository | [Work in a monorepo](monorepo.md) |
| Agree on interfaces between components | [Define and evolve contracts](contract-driven-development.md) |
| Keep implementation within manageable context limits | [Implement complex features](complex-features.md) |
| Decompose work into independently specified slices | [Break down large features](spec-of-specs.md) |
| Decide how completed specifications should live | [Choose a persistence model](spec-persistence.md) |
| Keep feature artifacts aligned after delivery | [Maintain specifications after delivery](evolving-specs.md) |
| Find what behaviour is in force, which change set it and what covers it | [Keep a catalog of current behaviour](capabilities.md) |
| Keep each spec to one thing a person can do and check | [One spec, one slice](capabilities.md#one-spec-one-slice) |
| Follow every task of a spec and what each agent did | [See how far a spec has come](progress.md) |
| Adapt practices to your team's needs | [Adapt Spec Kit to your process](customization.md) |
